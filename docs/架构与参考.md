# V8 架构与参考

## 参考了什么

- [MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo)：参考把脚本、素材、字幕、合成串起来的制作流程。本项目对应为明确的需求状态、画面方案、真实本机合成任务与成片归档，没有复制其代码或接入其云模型配置。
- [Remotion](https://github.com/remotion-dev/remotion)：参考以程序化方式描述视频的思路。这里使用显式秒数和分段素材描述时间轴，没有安装Remotion或使用它的运行时。
- [FFmpeg官方文档](https://ffmpeg.org/ffmpeg.html)：实际使用的本机媒体处理工具，负责裁切、缩放、连接、配音轨与叠字幕。
- [Python SQLite官方文档](https://docs.python.org/3/library/sqlite3.html)：使用标准库的磁盘数据库与事务，日常运行不需要额外数据库服务。

这些项目用途不同，不宣称本交付已具备其全部能力，也不以关注量作为功能完成度。

## 结构

```text
launcher.py             桌面生命周期、单实例、引擎准备与独立用户数据
desktop/                桌面路径、下载校验、安装器配置与授权文本
app.py                  源码启动入口，固定绑定127.0.0.1
server/store.py         数据校验、SQLite事务、版本冲突、记录快照
server/media.py         内置样片适配、本地导入、素材信息与自动封面
server/render.py        单工作线程的FFmpeg任务、真实进度、取消、归档
server/backup.py        完整备份、预览、冲突策略、素材校验与重映射
server/http.py          同源API、媒体范围请求、制作任务包
server/composition.py   服务端取景与字幕约定
界面/composition.mjs    浏览器对应约定、段落定位与素材循环
界面/preview.mjs        以歌曲为时钟的原生音画预览
界面/core.mjs           可独立测试的时间轴与计划校验
界面/client.mjs         请求、上传、下载、提示与确认
界面/editor.mjs         制作方案交互
界面/library.mjs        片库、素材与作品导入
界面/studio.js          页面协调、首页草稿、看板与备份界面
tests/                  存储/API/合成集成测试与时间轴契约
data/                   用户私有运行数据，打包与Git默认排除
```

## 数据约定

- 所有修改都先校验。已有记录需要匹配revision，旧窗口不会悄悄覆盖新窗口。
- 一个作品注册与其需求完成状态在同一事务中写入。
- 归档保留数据；当前版本不提供不可恢复的媒体删除。
- 备份先预览再恢复；相同素材编号但内容不同会分配新编号，并重映射相关引用。
- 记录快照用临时文件写入后原子替换；媒体备份另行导出，避免误把仅有记录快照当作完整媒体备份。
- 合成以保存后的方案为快照，期间锁定编辑。进度基于FFmpeg的实际输出时间，服务重启不会假装任务仍在运行。
- 本地服务拒绝其他网站的来源和未知Host，写接口还需当前会话令牌；data目录不作为静态文件暴露。
- 不提供公网、多用户或团队服务的安全承诺；当前交付针对用户自己的电脑。

## 后续扩展点

后续可在明确需求后增加字幕自动对齐、转场与图片运动、素材搜索和可选AI服务。它们不影响当前“手动决定画面、实际本机输出”的基本流程。接云服务之前需另行确定供应商、费用和数据传输范围。
